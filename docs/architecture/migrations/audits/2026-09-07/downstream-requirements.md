## Shared mandatory process

- Recompute current source, imports, signatures, serialization, consumers and tests; document drift from approximate candidate counts. Search released library APIs by behavior before creating anything new.
- Phase 1 changes only the target package, preserves approved behavior, uses the explicitly assigned namespace and moves its behavioral tests. Required deliverables include charter, full public API documentation and machine-readable API/capability/service manifests, examples, compatibility/security policies, changelog, architecture checks and complete v2 migration handoff.
- Open a draft package PR, put its observed URL and `draft_pr_open` in the committed handoff, run all package quality/security/archive/no-dev classmap-authoritative clean-consumer gates on the final head, make review-ready, and stop. No agent merge, invented release metadata or premature App adoption.
- A human merge and automated immutable release are followed by independent release verification and external `RELEASE-ATTESTATION.yaml`. `package-released` alone does not permit dependent publication or adoption. Each selected upstream dependency needs its released handoff plus attestation; genuine pre-v2 dependencies require documented `VERIFIED-LEGACY-RELEASE.yaml`.
- Phase 2 is App-only, consumes verified immutable releases with exact pins while pre-1.0, updates Composer through Composer, and removes moved implementation and package-class unit tests. App retains tests of composition, authority, database, deployment, recovery and delivery. Newer App portable behavior must first be released upstream in a separate task.
- No historical aliases, remaps, copied vendor classes, shadow implementations, production fallbacks or duplicate ownership. DI is only for actual injected runtime services; values/ports/stateless direct objects do not acquire empty providers. App capability index, migration ledger, changelog and objective evidence must be maintained. Extraction is enabling-refactor, not functional objective completion.

## Native constraints

Business Definition owns semantic formulas, Query owns safe query semantics, Reporting owns reports, and Computation owns coarse compile/execute contracts and plan identity. Engine executes bounded immutable programs; kumwe-engine owns only FQCNs explicitly assigned in the joint manifest. Each public FQCN must appear once across PHP archives and Zend registration.

Native executors may receive only validated immutable generations and already authorized/resolved bounded document or columnar batches. They cannot resolve records, authorize, emit SQL, access databases/filesystems, perform DDL, persist, audit, dispatch, choose trusted generations or call PHP per field/expression/row. App invalidates plans; identities include generation/schema checksums, semantic/API version, corpus and Engine compatibility. Test-only differential oracles are excluded from distributed runtime. Missing/incompatible required native execution fails readiness; no production PHP fallback.

1. Automation's generic DI row/prompt mentions providers for “workers”, while its specific exclusions explicitly keep host workers in App. Do not treat the generic row as permission to extract a daemon or trusted-generation worker.
2. Administrator's brief conditionally discusses a Navigation signature edge, but its stated ceiling/prompt lists only four dependency families. Prefer App composition; any required Navigation edge needs an explicit reconciled dependency decision rather than silently broadening Composer.
3. Record Query acceptance says Reporting consumes released Query, but Reporting's enumerated dependency ceiling excludes Record Query and the Query narrative also allows App composition. Prefer composing them in App unless the controlling catalog and refreshed closure explicitly authorize a package edge.
4. Generic Phase 2 prompt mentions documented “alias configuration”, while controlling rules prohibit aliases/remaps. This cannot authorize historical namespace aliases; use only legitimate documented container interface bindings that preserve canonical ownership.
